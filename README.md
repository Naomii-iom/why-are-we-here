# Why Are We Here?

AI can now write working code from a short description. As a design student, this creates a question that feels practical rather than theoretical: if I can describe an interaction and receive code from AI, why should I still learn programming?

At first, I thought programming might become less important for designers. I imagined that my role would be to have an idea, explain it in natural language, and let AI turn it into a working system. In this situation, learning to code seemed unnecessary. I would not need to memorise syntax or write every line myself. However, one of my own projects changed this view.

I worked on an interactive-screen project for a subway passage. There were screens on both sides of the passage, and I had a specific idea for how people should interact with them. Instead of building the interaction from scratch, I asked AI to generate code for it. This felt efficient at the beginning. I could explain the effect I wanted and quickly receive something that looked like a possible solution.

The problem appeared when the code did not work. I knew that the result was wrong, but I did not know why. I could only tell the AI, “It doesn't work,” and ask it to change the code again. The AI suggested different versions, but I could not tell whether those changes made sense. I was not able to identify the part of the program causing the problem, or to explain precisely what should happen instead.

Eventually, I asked someone else to look at the code. They found that a single number was wrong. The mistake was small, but I had no way to locate it myself: I could see that the interaction failed, yet I could not connect the visible problem to a particular value or condition in the program. That was the moment I understood that using AI to produce code did not give me control over the system.

The problem was not simply that AI was not intelligent enough. The more important problem was that I was treating the code as a black box. I could describe a desired result, but I could not judge how the result was being produced. I could ask AI to make changes, but I could not evaluate whether its answers were reasonable. I had access to a powerful tool, but I did not have enough knowledge to control it.

Dylan Beattie’s talk *The Art of Code* expands this question beyond whether programming is useful or efficient. He presents code as more than a tool for making practical software: code can also create patterns, music, images, games, and new forms of expression. Examples such as generative art and live coding show that programming can be a creative medium in its own right (Beattie, 2020). This is important to me as a designer because it changes how I think about code. Code is not only something hidden behind a finished interface. It is also part of the material from which an interactive experience can be made.

For this reason, I think designers should learn programming now not because we need to compete with AI at writing code faster. AI may often be faster. The value of learning programming is learning the principles behind a digital system. When I understand the basic logic of a program, I can read what AI gives me, test it, find problems, and decide whether it meets my design intention.

Programming also helps a designer communicate more clearly. Before learning programming, I might describe an idea by saying that I want an interaction to feel interesting or responsive. Those words are useful, but they are not enough to create a precise system. Programming makes me ask more specific questions: What is the user's input? What event triggers the interaction? What should change on the screen? What conditions must be true? When does the interaction end or reset?

This changes a design idea from a vague description into a specification. It does not reduce creativity. Instead, it helps make creativity possible in a real digital environment. If I can explain an interaction clearly, I can work more effectively with AI, programmers, and other collaborators. I can also notice when the output does not match the idea I had in mind.

Learning programming is also useful because it gives knowledge that can move between projects. I may not remember every command in a particular tool, and AI can help with details when I forget them. However, ideas such as input, condition, logic, output, and error can be used in many different situations. They can help me think about an interactive screen, a website, a game, or another design problem that I have not encountered before.

Therefore, I do not think we are here to become faster than AI at typing code. We are here to understand code as a medium. I want to be able to use AI without depending on it blindly. I want to judge its suggestions, explain my own intentions accurately, and understand enough to change a system when it fails. My subway-screen project showed me that a small error can become impossible to solve when code is only a black box. Learning programming is a way to make that box more visible, understandable, and usable.
